# API Contract — Fridgy

## 1. Загальна інформація

Backend Fridgy реалізований за допомогою FastAPI (Python). Мобільний застосунок взаємодіє із сервером через HTTP API. Для генерації рецептів використовується Google Gemini API.

**Base URL:**
- Android Emulator: `http://10.0.2.2:8000/`
- Локальний сервер: `http://127.0.0.1:8000/`
- Swagger: `http://127.0.0.1:8000/docs`

## 2. API Endpoints

### GET /health

Перевірка доступності Backend.

Успішна відповідь (200):

```json
{
  "status": "ok"
}
```

### POST /recipe

Генерація трьох варіантів рецептів на основі продуктів користувача та доступного часу.

**Request:**

```json
{
  "ingredients": [
    "куряче філе",
    "рис",
    "печериці",
    "вершки"
  ],
  "max_time_minutes": 40
}
```

**Валідація запиту:**

| Поле | Тип | Обмеження |
|---|---|---|
| ingredients | List<String> | Від 1 до 30 продуктів |
| Назва продукту | String | До 50 символів |
| max_time_minutes | Integer | Від 5 до 180 хвилин |

Сервер очищує назви продуктів, прибирає зайві пробіли та дублікати.

## 3. Формат успішної відповіді

HTTP 200 OK.

Backend повертає JSON-масив рівно з трьох об'єктів:

```json
[
  {
    "recipe_name": "Курка з грибами",
    "cooking_time_minutes": 30,
    "ingredients": [
      "Куряче філе — 300 г",
      "Печериці — 150 г"
    ],
    "instructions": [
      "Підготуйте інгредієнти.",
      "Обсмажте курку.",
      "Додайте гриби та доведіть до готовності."
    ],
    "source": "gemini"
  }
]
```

Приклад показує структуру одного елемента масиву.

**Вимоги до кожного рецепта:**
- Наявність назви страви.
- Непорожній список інгредієнтів.
- Від 3 до 10 кроків приготування.
- Час не перевищує обмеження користувача.
- Три рецепти повинні мати різні назви.

## 4. Обробка помилок

| HTTP | Значення | Опис |
|---|---|---|
| 422 | Validation Error | Некоректні вхідні дані |
| 429 | Too Many Requests | Перевищено ліміт запитів Gemini |
| 502 | Bad Gateway | Помилка генерації або обробки відповіді AI |
| 503 | Service Unavailable | Gemini недоступний або не налаштований API-ключ |
| 504 | Gateway Timeout | Перевищено час очікування відповіді AI |

## 5. Інтеграція з Android

Мережевий шар реалізований за допомогою Retrofit та Gson.

Основні компоненти:

- `FridgyApi.kt` — опис HTTP-запитів.
- `RetrofitClient.kt` — конфігурація Retrofit.
- `RecipeRequest.kt` — модель запиту.
- `RecipeResponse.kt` — модель одного рецепта.
- `RecipeRepository.kt` — отримання списку рецептів.
- `RecipeViewModel.kt` — керування станами UI.

Метод отримання рецептів повертає:

`List<RecipeResponse>`

Стан успішного завантаження:

`RecipeUiState.Success(recipes: List<RecipeResponse>)`

Jetpack Compose відображає отримані рецепти у вигляді трьох окремих карток.

## 6. Обмеження та безпека

- Gemini API Key зберігається на Backend у файлі `.env`.
- API Key не передається мобільному застосунку.
- Android Emulator звертається до локального сервера через `10.0.2.2`.
- Кожен рецепт проходить серверну перевірку часових обмежень.
- Кількість рецептів у відповіді має дорівнювати трьом.

## 7. Поточний статус

API успішно перевірено через Swagger: отримано HTTP 200 та три рецепти.

Мобільний застосунок успішно отримує та відображає три рецепти через Retrofit.

Обробку HTTP 429 перевірено на Android Emulator. Повторний тест генерації з лімітом 30 хвилин очікує відновлення квоти Gemini.
