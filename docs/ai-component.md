
# Fridgy — AI Component

## 1. Загальна інформація

AI-компонент Fridgy використовує Google Gemini API для генерації рецептів на основі продуктів користувача.

AI є основною інтелектуальною складовою застосунку.

Він аналізує доступні продукти, враховує обмеження часу та формує структурований рецепт українською мовою.

## 2. AI Technology

Використані технології:

- Google Gemini API.
- Google GenAI Python SDK.
- Structured JSON output.
- Pydantic response validation.

Модель налаштовується через змінну GEMINI_MODEL.

Модель за замовчуванням: gemini-3.8-flash.

Рівень thinking: low.

Максимальна кількість вихідних токенів: 900.

## 3. AI Input

Gemini отримує два основні параметри:

- ingredients — список продуктів користувача.
- max_time_minutes — максимальний час приготування.

Також у prompt зазначається кількість порцій: 1–2.

## 4. Prompt Engineering

Backend формує prompt із такими інструкціями:

1. Створити один реалістичний рецепт українською мовою.
2. Використовувати продукти користувача як основу.
3. Не вимагати інших основних продуктів, яких немає у списку.
4. Сіль, перець, вода та олія можуть бути необов'язковими.
5. Не вигадувати наявність інших продуктів.
6. Загальний час не повинен перевищувати заданий ліміт.
7. Вказувати приблизну кількість інгредієнтів.
8. Давати від 3 до 7 коротких кроків приготування.
9. Для м'яса, птиці, риби та яєць забезпечувати достатню термічну обробку.
10. Повернути лише структуровані JSON-дані.

## 5. Structured Output

Для генерації використовується Pydantic-модель GeneratedRecipe.

Структура результату:

- recipe_name — назва страви.
- cooking_time_minutes — час приготування.
- ingredients — список інгредієнтів.
- instructions — послідовність приготування.

Gemini налаштовується на повернення application/json із заданою схемою.

## 6. AI Response Validation

Після отримання відповіді backend виконує додаткові перевірки:

- Перевіряє наявність назви страви.
- Видаляє зайві пробіли.
- Перевіряє наявність інгредієнтів.
- Видаляє порожні елементи списків.
- Перевіряє кількість кроків приготування.
- Перевіряє, щоб час був більшим за нуль і не перевищував ліміт користувача.

Якщо відповідь не відповідає вимогам, генерація вважається невдалою.

Примітка: prompt просить від 3 до 7 кроків, тоді як серверна перевірка приймає від 3 до 10 кроків.

## 7. Time Constraint

Час приготування є одним із головних параметрів Fridgy.

Backend передає максимальний час у prompt Gemini.

Після генерації сервер окремо перевіряє:

cooking_time_minutes <= max_time_minutes

Якщо AI повертає час, що перевищує ліміт, результат відхиляється.

Це серверна перевірка заявленого моделлю часу, а не фактичне вимірювання тривалості приготування.

## 8. Error Handling

Backend передбачає обробку таких ситуацій:

- Порожня відповідь AI.
- Некоректна JSON-відповідь.
- Відсутність API-ключа.
- Перевищення часу очікування.
- Тимчасова недоступність Gemini.
- Перевищення ліміту запитів.

Основні HTTP-коди:

- 429 — перевищення ліміту Gemini.
- 502 — помилка генерації.
- 503 — AI не налаштований або недоступний.
- 504 — тайм-аут.

## 9. AI Configuration

Налаштування зберігаються у backend/.env:

- GEMINI_API_KEY — ключ доступу до Gemini.
- GEMINI_MODEL — назва AI-моделі.
- AI_TIMEOUT_S — час очікування відповіді.

Стандартний час очікування: 180 секунд.

API-ключ не повинен зберігатися в Android-застосунку.

## 10. Current Limitations

Поточна реалізація має такі обмеження:

- За один запит генерується один рецепт.
- Немає генерації декількох альтернативних страв.
- Час приготування визначається AI та перевіряється програмно, але не вимірюється фактично.
- Немає підтвердженої реалізації довготривалої пам'яті AI.
- Немає підтвердженої персоналізації на основі історії користувача.

## 11. Future Improvements

Заплановані можливості:

- Генерація трьох альтернативних рецептів.
- Точніше дотримання часового обмеження.
- Покращення різноманітності страв.
- Додавання дієтичних уподобань.
- Персоналізація рекомендацій.
