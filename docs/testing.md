# Testing — Fridgy

## 1. Загальна інформація

Тестування Fridgy проводиться для перевірки роботи Android-застосунку, Backend API та інтеграції з Google Gemini.

Тип тестування:
- Manual Testing.
- API Testing.
- Integration Testing.
- UI Testing.
- Error Handling Testing.

Тестове середовище:
- Android Studio.
- Android Emulator — Pixel 7 API 35.
- Kotlin.
- Jetpack Compose.
- Python.
- FastAPI.
- Google Gemini API.
- Retrofit.

## 2. Тестування Backend API

Основний endpoint: POST /recipe.

| № | Тест | Очікуваний результат | Результат |
|---|---|---|---|
| 1 | Надсилання коректного запиту | HTTP 200, три рецепти у відповіді | Пройдено |
| 2 | Перевірка JSON-відповіді | Повертається масив рецептів | Пройдено |
| 3 | Перевірка обмеження часу | Кожен рецепт відповідає часовому ліміту | Не перевірено окремо |
| 4 | Перевірка HTTP 429 | Повертається повідомлення про ліміт AI-запитів | Пройдено |
| 5 | Перевірка HTTP 503 | Повідомлення про тимчасову недоступність Gemini | Пройдено |

## 4. Тестування обробки помилок

Під час розробки було виявлено та перевірено такі ситуації:

**1. Недоступність сервера**

Під час відсутності з'єднання застосунок відображає повідомлення про неможливість отримати відповідь від сервера.

**2. Тимчасова недоступність Gemini**

Backend отримував HTTP 503 від Google Gemini API. Помилка обробляється сервером.

**3. Перевищення ліміту AI-запитів**

Під час тестування було отримано HTTP 429 RESOURCE_EXHAUSTED.

Застосунок відображає повідомлення:

«Вичерпано денний ліміт AI-запитів. Спробуйте пізніше».

Це пов'язано з обмеженнями квоти Google Gemini API.

## 5. Результати інтеграційного тестування

Перевірено основний сценарій взаємодії компонентів:

1. Користувач вводить продукти та максимальний час приготування.
2. Android-застосунок формує POST-запит.
3. Backend отримує та обробляє запит.
4. Gemini генерує варіанти рецептів.
5. Backend повертає JSON-відповідь.
6. Android отримує дані та відображає рецепти.

Під час успішного запиту було отримано HTTP 200 та масив із трьома рецептами.

На мобільному екрані реалізовано відображення трьох ідей для приготування.

## 6. Висновок

У результаті тестування перевірено основний функціонал Fridgy, взаємодію Android-застосунку з Backend API та інтеграцію з Google Gemini.

Підтверджено можливість передавання продуктів, отримання трьох варіантів рецептів та їх відображення в інтерфейсі.

Також перевірено обробку мережевих помилок і ситуацій, пов'язаних із тимчасовою недоступністю AI та перевищенням квоти запитів.

Окремі перевірки часових обмежень, граничних значень і автоматизовані unit-тести залишаються наступними етапами тестування.
