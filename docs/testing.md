# Testing — Fridgy

## 1. Загальна інформація

Тестування Fridgy проводиться для перевірки роботи Android-застосунку, Backend API, інтеграції з Google Gemini та локального збереження історії.

Тип тестування:
- Manual Testing.
- API Testing.
- Integration Testing.
- UI Testing.
- Error Handling Testing.

Тестове середовище:
- Android Studio.
- Android Emulator — Pixel 7 API 35.
- Kotlin.
- Jetpack Compose.
- Room.
- Python.
- FastAPI.
- Google Gemini API.
- Retrofit.

## 2. Тестування Backend API

## 4. Тестування обробки помилок

Під час розробки було виявлено та перевірено такі ситуації:

**1. Недоступність сервера**

Під час відсутності з'єднання застосунок відображає повідомлення про неможливість отримати відповідь від сервера.

**2. Тимчасова недоступність Gemini**

Backend отримував HTTP 503 від Google Gemini API (повідомлення про високе навантаження на модель). Помилка обробляється сервером і показується користувачу як тимчасова.

**3. Перевищення ліміту AI-запитів**

Під час тестування було отримано HTTP 429 RESOURCE_EXHAUSTED.

Застосунок відображає повідомлення:

«Вичерпано денний ліміт AI-запитів. Спробуйте пізніше».

Це пов'язано з обмеженнями квоти Google Gemini API.

## 5. Результати інтеграційного тестування

Перевірено основний сценарій взаємодії компонентів:

1. Користувач вводить продукти та максимальний час приготування.
2. Android-застосунок формує POST-запит.
3. Backend отримує та обробляє запит.
4. Gemini генерує варіанти рецептів.
5. Backend повертає JSON-відповідь.
6. Android отримує дані та відображає рецепти.

Під час успішного запиту було отримано HTTP 200 та масив із трьома рецептами.

На мобільному екрані реалізовано відображення трьох ідей для приготування.

## 6. Тестування локальної історії (ЛР4)

Дата перевірки: 14.11.2026.
Середовище: Android Emulator Pixel 7 API 35, Backend запущений локально.
Метод: ручне тестування на емуляторі.

| № | Сценарій | Очікуваний результат | Фактичний результат | Статус |
|---|---|---|---|---|
| 1 | Порожня історія | Зрозуміле повідомлення замість порожнього екрана | Показано повідомлення «Історія поки порожня...» (перевірено після очищення історії) | Виконано |
| 2 | Успішний запит | Три рецепти на головному екрані; у історії з'являється запис | Рецепти відображено; запис додано з датою, продуктами, лімітом часу та назвами страв | Виконано |
| 3 | Деталі запису | Відкриваються вхідні дані й усі три рецепти, є позначка збереженого результату | Екран деталей показує запит і три рецепти з позначкою «Збережений результат від ...» | Виконано |
| 4 | Два різні запити | Два записи, кожен зі своїми даними; новіший зверху | Створено два записи, новіший відображається першим | Виконано |
| 5 | Перезапуск застосунку | Записи залишаються після повного закриття | Після закриття застосунку з переліку останніх і повторного відкриття записи збереглися | Виконано |
| 6 | Помилка Backend | Помилка не зберігається в історію | Сервер зупинено; застосунок показав помилку з'єднання; нових записів в історії не з'явилось | Виконано |
| 7 | Видалення одного запису | Діалог підтвердження; запис зникає й не повертається після перезапуску | «Скасувати» залишає запис; після підтвердження запис видалено; після перезапуску його немає | Виконано |
| 8 | Очищення історії | Діалог підтвердження; після підтвердження історія порожня | Усі записи видалено, показано порожній стан | Виконано |
| 9 | Основний сценарій ЛР2–ЛР3 | Генерація трьох рецептів працює як раніше | Генерація та відображення трьох карток працюють | Виконано |

Скриншоти до сценаріїв додаються у звіт до лабораторної роботи.

Не перевірено:
- Автоматизовані тести (unit/instrumented) не створювалися.
- Перевірка зміни схеми бази (міграції): схема має версію 1, міграцій немає.
- Підвищений рівень (запити без мережі зі статусом «очікує») не реалізований.

## 7. Висновок

У результаті тестування перевірено основний функціонал Fridgy, взаємодію Android-застосунку з Backend API та інтеграцію з Google Gemini.

Підтверджено можливість передавання продуктів, отримання трьох варіантів рецептів та їх відображення в інтерфейсі.

Також перевірено обробку мережевих помилок і ситуацій, пов'язаних із тимчасовою недоступністю AI та перевищенням квоти запитів.

Додатково перевірено локальну історію: збереження лише успішних результатів, перегляд списку й деталей, збереження даних після перезапуску, видалення одного запису та очищення історії.

Окремі перевірки часових обмежень, граничних значень і автоматизовані unit-тести залишаються наступними етапами тестування.
