# 🥑 Fridgy

### Твоя кухня тепер має власний інтелект.

**Fridgy** — концепція мобільного AI-помічника, який допомагає швидко вирішити, що приготувати з продуктів, які вже є вдома. Менше часу на пошук рецептів, менше зайвих покупок і більше смачних ідей на щодень.

> **Статус проєкту:** працює демонстраційний Android-застосунок із головним екраном, прикладом інгредієнтів та інтерактивним показом рецепта. Генерація рецептів за допомогою AI, камера та цифровий холодильник — **заплановані можливості, які ще не реалізовані**.

---

## 💡 Ідея

Знайома ситуація: вдома є яйця, помідори, сир і макарони, але незрозуміло, що приготувати? Замість довгого пошуку Fridgy має пропонувати кілька доречних варіантів з урахуванням:

- 🧺 **наявних інгредієнтів** та їхньої кількості;
- ⏱️ **часу**, який є на приготування;
- 🍽️ **кількості порцій**;
- 💚 **смакових вподобань** та зазначених обмежень;
- 🥬 **продуктів, які бажано використати найближчим часом**.

**Головна мета:** не просто показати рецепт, а допомогти прийняти щоденне рішення — *«Що мені приготувати саме зараз?»*

## 📱 Як виглядає застосунок зараз

На поточному етапі реалізовано:

- головний екран у світлій, теплій кольоровій гамі;
- демонстраційний перелік продуктів: **яйця, помідори та сир**;
- кнопку **«Що приготувати? ✨»**;
- відображення та приховування **попередньо заданого рецепта** після натискання кнопки.

*Поточний екран — концептуальний прототип. Рецепт демонстраційний і поки не створюється нейромережею.*

## 🛠️ Технології

**Використано зараз**

- **Kotlin** — мова розробки Android-застосунку.
- **Jetpack Compose** — створення інтерфейсу.
- **Material 3** — компоненти оформлення.
- **Android Studio** — середовище розробки.
- **Android Emulator** — тестування на віртуальному Pixel 7 з Android 15 (API 35).

**Передбачено концепцією**

- **Python + FastAPI** — серверне API та перевірка вхідних даних.
- **AI-модель** — аналіз інгредієнтів і формування структурованих рекомендацій.
- **Room** — локальне зберігання історії запитів і рецептів.
- **CameraX / Vision AI** — робота з камерою та розпізнавання продуктів.

## 🚀 Як запустити проєкт

1. Встанови [Android Studio](https://developer.android.com/studio).
2. Клонуй репозиторій:

   ```bash
   git clone https://github.com/tshynderuk/Fridgy.git
   ```

3. В Android Studio вибери **Open** та відкрий папку `Fridgy`.
4. Дочекайся завершення **Gradle Sync**.
5. Створи Android-емулятор або підключи фізичний Android-пристрій.
6. Вибери конфігурацію **app** і натисни **Run ▶**.
7. На головному екрані натисни **«Що приготувати? ✨»**, щоб відкрити демонстраційний рецепт.

> Для поточної версії не потрібні сервер, API-ключі або реєстрація.

## Запуск проєкту Fridgy

### 1. Технології

**Mobile:**
- Kotlin
- Android Studio
- Jetpack Compose
- Material 3
- Retrofit
- Gson
- MVVM

**Backend:**
- Python
- FastAPI
- Uvicorn
- Pydantic
- Google Gemini API

### 2. Налаштування Backend

Відкрити папку `backend` у терміналі.

Створити віртуальне середовище (якщо ще не створене):

```powershell
python -m venv .venv
```

Активувати середовище:

```powershell
.\.venv\Scripts\Activate.ps1
```

Встановити необхідні залежності:

```powershell
pip install fastapi "uvicorn[standard]" python-dotenv google-genai
```

### 3. Налаштування API Key

У папці `backend` створити файл `.env`.

Приклад конфігурації:

```env
GEMINI_API_KEY=YOUR_API_KEY
GEMINI_MODEL=YOUR_MODEL_NAME
AI_TIMEOUT_S=180
```

Замість `YOUR_API_KEY` потрібно вказати власний ключ Google Gemini.

Файл `.env` не повинен потрапляти до Git-репозиторію.

### 4. Запуск Backend

Перебуваючи в папці `backend`, виконати:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Backend буде доступний за адресою:

`http://127.0.0.1:8000`

Перевірка працездатності:

`http://127.0.0.1:8000/health`

Swagger API:

`http://127.0.0.1:8000/docs`

### 5. Запуск Android-застосунку

1. Відкрити проєкт у Android Studio.
2. Дочекатися завершення Gradle Sync.
3. Запустити Android Emulator.
4. Вибрати пристрій Pixel 7 API 35.
5. Натиснути Run.

Для Android Emulator використовується адреса:

`http://10.0.2.2:8000/`

Вона забезпечує підключення емулятора до локального Backend комп'ютера.

### 6. Перевірка функціональності

Для перевірки основного сценарію:

1. Запустити Backend.
2. Запустити Android-застосунок.
3. Ввести доступні продукти.
4. Вказати максимальний час приготування від 5 до 180 хвилин.
5. Натиснути кнопку «Запропонуй 3 страви».
6. Перевірити відображення трьох рецептів.

Кожен рецепт повинен містити:
- Назву страви.
- Час приготування.
- Інгредієнти.
- Інструкції.

Час кожного рецепта не повинен перевищувати встановлений користувачем ліміт.

### 7. Обробка помилок

Застосунок передбачає обробку таких ситуацій:

- HTTP 422 — помилка вхідних даних.
- HTTP 429 — перевищення квоти Gemini API.
- HTTP 502 — помилка генерації AI.
- HTTP 503 — тимчасова недоступність AI.
- HTTP 504 — перевищення часу очікування.
- IOException — відсутність мережевого з'єднання.

### 8. Поточний стан проєкту

Реалізовано:

- Встановлення максимального часу приготування.
- Підключення Android до Backend API.
- Інтеграцію з Google Gemini.
- Генерацію трьох варіантів рецептів.
- Відображення результатів у Jetpack Compose.
- Обробку помилок сервера та мережі.
